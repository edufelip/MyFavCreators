# Architecture decision records

One file per decision, numbered in order. A decision that later turns out to be wrong gets a
new ADR that supersedes the old one; existing records are not rewritten.

Write an ADR before, not after, doing any of these:

- replacing a pinned tool or library named in the product specification
- adding a linter or formatter alongside Biome
- introducing a new application, service or worker
- introducing shared infrastructure such as Redis
- changing the ranking model, the money representation or the payment state machine
